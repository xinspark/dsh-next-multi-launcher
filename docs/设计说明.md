## 1. 目标与非目标

### 1.1 目标

1. 管理 N 个**原生 DSH-NEXT 实例**：真窗口、真托盘、真 Community Market，不是 webview 套壳。
2. 每个实例独立设置：**名称 / 数据目录（home）/ 壳版本**。
3. 实例间**数据完全隔离**：会话、Bot 团队、凭据、日志、插件 profile、窗口状态各一份。
4. 一键启动、停止、归档、删除；随时可见"哪些在跑、全局指针指向哪"。

### 1.2 非目标

| 不做 | 原因 |
|---|---|
| 账号隔离 | 官方：切 home 不隔离 Agents Anywhere 的登录与设备绑定 |
| 内核与壳分离 | 官方：Electron 与 `@deepseek-ai/dsh` 始终同版本 → 一个版本旋钮 |
| 同 home 多实例 | 两个 writer 会损坏会话（seq-gap） |
| 修改 DSH 本体 | 不碰 `app.asar` / 安装目录 / 快捷方式 / 注册表 |
| 自动更新管理 | v1.0 只提示风险，不改 `app-update.yml` |

## 2. 机制原理（实测，不是推测）

### 2.1 指针文件

```
路径  %APPDATA%\DSH NEXT\home\desktop-next-location.json
格式  { "home": "C:\\Users\\<用户名>\\.dsh-b" }        （2 空格缩进，UTF-8 无 BOM）
时机  DSH-NEXT 只在**进程启动时读一次**；之后改动不影响运行中的实例（实测：改指针后原实例纹丝不动）
优先级 应用内选择 > 环境变量 DSH_DESKTOP_NEXT_HOME > 默认 ~/.dsh
```

同目录还有 `desktop-next-last-home.json`（应用自己写，记录上次用过的 home），形状相同；启动器**不写**它，只读。

### 2.2 home → userData → 锁

```
home          = 指针里的路径
userData      = <home>\electron-user-data        ← 进程命令行可见
单实例锁      = Electron 以 userData 路径为身份（Chromium DIR_USER_DATA）
```

所以**不同 home = 不同 userData = 两把不同的锁 → 两个实例都能是 primary**。不需要 `--user-data-dir`，不需要复制安装目录。

### 2.3 为什么环境变量不可用（本版）

`DSH_DESKTOP_NEXT_HOME` 确实传进了进程（cmd 探针验证），但 DSH-NEXT 启动后会**自我重启一次**：父进程（我们启动的那个）退出，子进程接管并显示窗口。重启后环境变量丢失，设置页来源显示「默认」。

**结论：唯一可控入口是那张指针文件，且必须在启动前写好。**

### 2.4 启动进程模型

```
spawn "DSH NEXT.exe"
  └─ 父进程（约 2–12 秒）→ 退出
       └─ 子进程 = 真正的 main（拥有窗口）
            ├─ gpu / renderer / network（--user-data-dir=<home>\electron-user-data）
            └─ host（--expose-internals <asar>\lib\host.js <asar> <home>\profiles\<profile> <runtime 目录>）
```

**判据：不能看 `spawn` 返回的 pid 是否存活，要看"目标 home 下有没有 host 进程"。**

### 2.5 三行算法

```
1. 写指针 = { home: X }
2. spawn <版本目录>\DSH NEXT.exe
3. 轮询直到出现 --user-data-dir=<X>\electron-user-data 的进程 → 成功
```

约束：**1 与 2 之间不能被另一次启动插入**。指针全局一份，交错会导致两个实例落进同一个 home。

## 3. 名词

| 名词 | 含义 |
|---|---|
| **版本** | 一份完整的 DSH-NEXT 安装树（`DSH NEXT.exe` + `resources\app.asar` + `resources\runtime`），对应一个 release tag，内核版本随之固定 |
| **实例** | "版本 + home"的组合，用户可见的一个窗口 |
| **home** | 数据目录；userData 在其下 `electron-user-data` |
| **指针** | 上述全局 JSON，决定**下一次**启动用哪个 home |
| **默认 home** | 全局配置里的 `defaultHome`，普通双击快捷方式应落入的环境 |

## 4. 数据模型

### 4.1 实例文件 `instances\<id>.json`

```json
{
  "schemaVersion": 1,
  "id": "lingshu",
  "name": "灵枢",
  "version": "2.0.21-next",
  "home": "C:\\Users\\<用户名>\\.dsh-lingshu",
  "archived": false,
  "createdAt": "2026-11-01T06:00:00+08:00",
  "lastLaunchAt": "2026-11-01T06:45:12+08:00",
  "lastExitClean": true,
  "notes": ""
}
```

| 字段 | 规则 |
|---|---|
| `id` | `[a-z0-9-]{1,32}`，创建后**不可改**；等于文件名；全局唯一 |
| `name` | 可改，可重名（提示但不拦） |
| `version` | 必须等于 `versions\` 下的某个目录名 |
| `home` | 绝对路径；不允许与其它**未归档**实例相同；不允许是盘根 |
| `archived` | true 时不在主列表显示 |
| `lastExitClean` | 供 UI 提示"上次非正常退出" |

### 4.2 全局配置 `app.json`

```json
{
  "schemaVersion": 1,
  "defaultHome": "C:\\Users\\<用户名>\\.dsh",
  "launchTimeoutSec": 90,
  "pollIntervalMs": 500,
  "restorePointerAfterLaunch": true,
  "lastPointer": { "home": "C:\\Users\\<用户名>\\.dsh", "at": "2026-11-01T06:45:12+08:00" }
}
```

- `restorePointerAfterLaunch`：启动成功后是否把指针还原为 `defaultHome`（**默认 true**，保证双击图标进日常环境）。
- `lastPointer`：用于崩溃后诊断"上次把指针写成了什么"。

### 4.3 版本条目（运行时扫描，不落库）

`versions\<tag>\` 目录扫描得到：

```json
{
  "tag": "2.0.21-next",
  "dir": "versions\\2.0.21-next",
  "exe": "versions\\2.0.21-next\\DSH NEXT.exe",
  "asar": "versions\\2.0.21-next\\resources\\app.asar",
  "shellVersion": "2.0.21-next",
  "kernelVersion": "0.2.1-rc.4",
  "valid": true,
  "invalidReason": null
}
```

`shellVersion` / `kernelVersion` **从 `app.asar!/package.json` 读**（`version` 与 `dependencies["@deepseek-ai/dsh"]`），**不手写**。

### 4.4 目录布局

```
<项目目录>\
  docs\设计说明.md  docs\实施计划.md  docs\env-check.md
  design\tokens.lock.json  design\controls.md  design\parts\
  tools\extract-tokens.mjs  tools\verify-tokens.mjs
  src-tauri\  src\  package.json  README.md

%LOCALAPPDATA%\DSH-NEXT-Multi\
  app.json
  instances\*.json
  logs\launcher-YYYYMMDD.log
  cache\versions.json        （扫描结果缓存，可删）
```

### 4.5 原子写

所有 JSON 写入：`写 <file>.tmp → flush → File.Move(tmp, file, overwrite)`。
指针额外保留 `desktop-next-location.json.launcher-bak`（启动器自己那份备份，重名冲突时优先用 `.bak2`/时间戳后缀）。

## 5. 核心模块

### 5.1 store

| 能力 | 签名 |
|---|---|
| 读配置 | `loadConfig() -> Config`（文件缺失时返回默认值并落盘） |
| 写配置 | `saveConfig(cfg)` 原子写 |
| 列实例 | `listInstances(includeArchived) -> Instance[]` |
| 读/写实例 | `readInstance(id)` / `writeInstance(inst)` |
| 校验 | `validateInstance(inst, all) -> Err?`（id 格式、home 唯一、version 存在、home 非盘根） |

### 5.2 pointer

```rust
struct PointerState { current: Option<PathBuf>, lastWritten: Option<PathBuf> }

fn read() -> Option<PathBuf>;                       // 解析失败返回 None + 记日志
fn write(home: &Path) -> Result<Backup>;            // 备份旧值，原子写
fn restore(backup: Backup) -> Result<()>;           // 失败回滚
fn restore_default(default_home: &Path) -> Result<()>;
```

规则：
- 写之前**必须**拿到旧值（文件不存在则记为 "absent"）；
- 写失败 → 立刻用备份还原，并把错误上报到 UI；
- 只允许启动管道与"恢复默认"按钮调用写；其它路径只读。

### 5.3 scan

```rust
struct RunningInstance { home: PathBuf, shell_pid: u32, host_pid: Option<u32>, started_at: SystemTime }
fn scan() -> Vec<RunningInstance>;
```

匹配规则（按顺序尝试）：

1. 进程名 `DSH NEXT.exe`；
2. 命令行含 `--user-data-dir="<home>\electron-user-data"` → 归入 home；
3. 命令行含 `--expose-internals` 且含 `<home>\profiles\` → 该进程是 host。

只认规则 2/3 的实际命中；**不缓存**，每次界面刷新重扫（几十毫秒）。启动器崩溃重启后仍能正确显示状态。

### 5.4 launcher（状态机）

```
Idle ──启动──> Queued ──出队──> Preparing ──写指针──> Spawning ──> Waiting ──> Running
                                  │                    │            │
                                  └─失败─> Failed <────┴────失败─────┘
```

| 状态 | UI | 允许的操作 |
|---|---|---|
| Idle | ○ 已停止 | 启动/归档/删除/编辑 |
| Queued | ◷ 排队中（第 N 位） | 取消 |
| Preparing | ◐ 准备中… | 取消 |
| Spawning | ◐ 启动中 0s | 取消（只停轮询，不杀已起进程） |
| Waiting | ◐ 启动中 12s… | 取消 |
| Running | ● 运行中 · 已运行 12 分钟 | 停止/归档/删除（后两者禁用） |
| Failed | ⚠ 失败（悬停看原因） | 重试/编辑/归档/删除 |

```text
launch(inst):
  if running(inst.home) -> E1003
  if any_other_instance_running(inst.home) -> E1003
  enqueue { inst, deadline = now + timeout }
  on_dequeue:
    backup = pointer.write(inst.home)        // E1001 / E1002
    p = spawn(inst.exe)                      // E1004
    t0 = now
    loop until now > deadline:
      if scan().contains(inst.home):
         if restorePointerAfterLaunch: pointer.restore_default()
         record(inst.id, shellPid, hostPid, t0)
         -> Running
      if p.exited && elapsed > 5s: -> Failed(E1006, 退出码)
      sleep(pollIntervalMs)
    -> Failed(E1005); pointer.restore(backup)
```

**失败一律回滚指针**；回滚本身失败 → `E1002`（严重，提示手工检查指针文件）。

### 5.5 versions

| 能力 | 说明 |
|---|---|
| `scan_versions()` | 遍历 `versions\*`，校验 `DSH NEXT.exe` + `resources\app.asar`，读版本号 |
| `import_version(dir)` | 校验后登记（可选：把目录复制进 `versions\`，默认不复制，只登记路径） |
| `remove_version(tag)` | 有实例引用 → 拒绝 |

版本号读取：解析 `app.asar` 头部 JSON（asar 格式：`[8字节头][JSON 索引]`），从索引里定位 `package.json` 后读取并解析；失败则 `kernelVersion = "?"`，不猜。

### 5.6 guard（路径安全）

```rust
fn assert_safe_delete_target(p: &Path, default_home: &Path) -> Result<()>;
```

拒绝条件：盘根（`C:\`）、`%APPDATA%` 及其上级、`%USERPROFILE%`、`defaultHome`、长度 < 8 的路径、含 `..` 的路径。

### 6.5 对话框

| 对话框 | 字段 |
|---|---|
| 新建实例 | 名称（必填）、ID（自动转写，可改，唯一校验）、版本（下拉）、home（默认 `%USERPROFILE%\.dsh-<id>`，可改） |
| 编辑 | 同新建，但 ID 只读 |
| 删除 | 输入实例 ID 确认；勾选"同时删除数据目录"（`defaultHome` 时锁定不可选）；显示将删除的绝对路径 |

### 6.6 顶栏与提示条

- 顶栏常显指针当前值（唯一会泄露到"普通双击"的全局状态）。
- 黄条条件：`defaultHome` 没有对应实例 → 「默认数据目录 X 没有对应实例，双击桌面图标会直接进入它」+ [按此目录新建]。
- 黄条条件：指针值 ≠ 任何实例 home 且无实例运行 → 「指针指向未知目录 X」+ [恢复默认]。

## 7. 视觉与原生对齐

### 7.1 取证方法

`tools\extract-tokens.mjs` 读 `app.asar`，抽：token 名册（`--ds*` / `--json*`）、半径/间距刻度、控件尺寸（卡片 16px、行 12px、小按钮 28px、chevron 12×12 viewBox 16 stroke 1）。每条记 `{name, valueType, source:{pkg,file,symbol}}`，输出 `design\tokens.lock.json`。

### 7.2 样式规则

- 只允许 `var(--ds…)` / `var(--json…)`；**禁 hex / rgb / 自造变量**。
- 半透明表面必须成对：fill + `backdrop-filter` + elevation，缺一会变全透明。
- 图标从官方 path 复制，不自绘。

### 7.3 对账门

`tools\verify-tokens.mjs`：扫描 `src\**\*.css|*.svelte` 里的每个 `var(--…)`，断言存在于 `tokens.lock.json`；同时校验 `design\parts\*` 的 sha256。缺席即失败（退出码 1）。

DSH-NEXT 升级流程：重跑 `extract-tokens` → diff → 重跑 `verify-tokens` → 通过才抬基线版本号。

## 8. 错误码与文案

| 码 | 场景 | 行内文案（中文） | 处理建议 |
|---|---|---|---|
| E1001 | 指针写入失败 | 无法写入数据目录指针（权限或占用） | 检查 `%APPDATA%\DSH NEXT\home` 是否只读 |
| E1002 | 指针回滚失败 | 指针回滚失败，请手工检查指针文件 | 显示文件路径；提供"恢复默认" |
| E1003 | home 已被占用 | 数据目录 X 已被实例「Y」使用 | 换 home 或先停止 Y |
| E1004 | 版本无效 | 版本目录无效：缺少 DSH NEXT.exe 或 app.asar | 重新导入版本 |
| E1005 | 启动超时 | 启动超时（90 秒内未看到该目录的进程） | 重试；仍失败看日志 |
| E1006 | 启动即退出 | 启动后进程立即退出（退出码 N） | 检查版本树完整性 |
| E1007 | 路径不安全 | 该路径不允许删除（盘根/系统目录/默认环境） | 只能删实例记录 |
| E1008 | ID 已存在 | 实例 ID 已存在 | 换一个 |

文案规则：中文人话 + 英文；错误截断 45 字符 + 悬停全文；不露堆栈、不露令牌。

## 9. 边界与承诺

- **能保证**：DSH 数据（会话/Bot/凭据/日志/插件/窗口状态）按 home 隔离；多实例可同时运行。
- **不能保证**：Agents Anywhere 登录与设备绑定（跨实例共享）；内核版本独立于壳版本；同 home 多实例安全。
- **不进 DSH 目录**：不写 `app.asar`、不改快捷方式、不写 DSH 相关注册表。
