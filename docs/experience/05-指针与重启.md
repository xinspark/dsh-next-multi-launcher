# 05 · 指针与重启

## 症状

非默认实例在 DSH-NEXT 内部点「重启 / 重启到恢复模式」后，落到了**默认**实例。

## 根因

启动器在**启动成功后**立刻把全局指针还原成 `defaultHome`（为了让双击桌面图标进日常环境）。
而 DSH-NEXT 的重启是"起一个新进程"，新进程启动时会**重新读指针文件**——此时指针已经是默认 home。

## 证据

- 现象可稳定复现（用户报告 + 手工验证）；
- DSH-NEXT 自身的重启实现（`lib/main.js`）会重新解析数据目录：
  `a directory chosen in the app wins, DSH_DESKTOP_NEXT_HOME applies only without one`；
- 即 home 由指针文件（应用内选择）决定，重启不携带原 home。

## 结论

- 指针在启动成功后还原是**有意设计**（双击图标进日常环境），代价是 DSH 内部重启会串台；
- 因此**非默认实例的重启统一由启动器发起**：停止 → 等进程消失 → 写指针 → 重新 spawn → 成功后还原；
- 多开时指针全局唯一，同时运行多个非默认实例时，只有最后启动的那个能正确重启——这是机制限制，已在界面提示条与 README 中标注。

对应实现：`launcher.rs::succeed`、`commands.rs::instance_restart`。
