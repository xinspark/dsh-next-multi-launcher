# 07 · 自动扫描扫不出中文路径

## 症状

社区用户（v1.0.1）点「自动扫描」后，候选列表里的路径是乱码，且全部被判为「无效目录」：

```
注册表   无效目录（缺少 DSH NEXT.exe 或 app.asar）   D:\豆包\Dsh...
快捷方式  无效目录（缺少 DSH NEXT.exe 或 app.asar）   D:\?????-
快捷方式  无效目录（缺少 DSH NEXT.exe 或 app.asar）   E:\DSH-?...
```

同样的构建在维护者机器上正常——维护者的机器装了 PowerShell 7。

## 根因

v1.0.1 的扫描用**一次 PowerShell 子进程**取快捷方式与注册表结果，再由 Rust 读它的 stdout。
PowerShell 5.1（Windows 自带）的控制台输出走系统 ANSI 代码页（简中为 GBK），
中文路径（`D:\豆包\…`、`E:\DSH-工具`）经 stdout 往返后被替换成 `?`，
Rust 侧拿到的路径不存在 → `inspect_dir` 校验失败 → 全部标为无效。

PowerShell 7 默认 UTF-8，所以维护者机器上看不出问题——这是「开发机正常、用户机失败」的典型编码差。

## 证据

- 用户截图：注册表来源的 `D:\豆包\Dsh` 尚可读（截断在 ASCII 边界前），两条快捷方式来源显示 `D:\?????-`、`E:\DSH-?...`；
- 维护者机器 `pwsh` 在 PATH 上，`--discover` 输出中文正常；
- 复现夹具（v1.0.2 开发期）：造 `target\中文测试\DSH 安装` + 桌面中文快捷方式，旧实现输出乱码，新实现输出
  `shellVersion=2.9.9-cn`、`valid=true`。

## 结论

- **不要用外部进程的 stdout 传递路径这类非 ASCII 数据**：编码由对方控制台决定，包装不住；
- 改为 Windows 原生 API，彻底去掉外部依赖（也回应了「换台电脑就不能用」的顾虑）：
  - 快捷方式：COM `IShellLinkW` + `IPersistFile`，`GetPath(..., SLGP_RAWPATH)` 直接取 UTF-16；
  - 注册表：`winreg` 读 `Uninstall` 键的 `InstallLocation` / `DisplayIcon`（去引号与 `,<index>`）；
- 新增回归用例 `chinese_paths_are_preserved`：把中文路径灌进唯一化逻辑，断言不被改写；
- 教训推广：凡是要跨进程边界传路径/文件名，要么走文件（显式 UTF-8），要么走原生 API，不要走控制台。
