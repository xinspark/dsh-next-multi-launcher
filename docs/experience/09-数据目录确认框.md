# 09 · 每次切换实例都弹「数据目录与上次不同」

## 症状

用启动器切换到另一个实例（另一个 home）时，DSH-NEXT 先弹一个模态：

```
数据目录与上次不同
本次：E:\...\.dsh-inst-xxx（default）
上次：C:\Users\<user>\.dsh
[改用上次的目录] [继续使用本次目录] [退出]
```

默认按钮是**「改用上次的目录」**——一路回车就会启动上一个实例，
而且这不只是烦：`E1005`/超时也会跟着出现（模态期间窗口进程起不来）。

## 根因

DSH-NEXT 2.0.x 起在固定目录维护两份记录：

```
%APPDATA%\DSH NEXT\home\desktop-next-location.json     # 本次进哪个 home
%APPDATA%\DSH NEXT\home\desktop-next-last-home.json    # 上次进的是哪个 home
```

`main()` 里 `await confirmDataDirectory()` 在开窗之前跑：
解析出的 home ≠ last-home、且上次那个目录里还有 Next 数据（`desktop-next.json`
或 `profiles\desktop\package.json`）就弹框。

启动器原来只写指针（location），不写 last-home，于是：

- 切实例：指针 = 新实例，last-home = 上一个实例 → 弹框；
- 启动成功后指针被还原成默认 home，last-home 还停在上一个实例 →
  下次**双击图标**也会弹框，默认按钮还会把启动改回那个实例。

## 证据

```text
# 代码（app.asar!/lib/main.js）
if (!await confirmDataDirectory()) return;   // 在 protocol.handle / 建窗之前
dataDirectoryChange(): previous = readHome(.../desktop-next-last-home.json)
if (sameDirectory(previous.home, home)) return undefined

# 实跑（homeG 实测）：窗口进程出现前弹框，用户点「继续使用本次目录」后才继续
```

## 结论

指针与 last-home **同写同回滚**（`pointer.rs::LastHome`、`launcher.rs::Worker::rollback`）：

- 写指针后立刻写 `desktop-next-last-home.json` = 同一个 home；
- 任何失败路径（E1004/E1005/E1006/取消）两份一起回滚；
- 启动成功后两份一起还原成默认 home，双击图标不会再被拦。
