## 1. 阶段 0 — 前置检查（半天）

**产物**：`docs\env-check.md`

| 步骤 | 动作 | 验收 |
|---|---|---|
| 0.1 | 在根目录建 `.probe` 文件再删除 | 两个命令都成功 → 目录可写 |
| 0.2 | 跑上表五个检查命令 | 结果逐条抄进 `env-check.md`（命令 + 实际输出 + 结论） |
| 0.3 | 判断改道 | Rust 缺失 → 走 WPF 分支；WebView2 缺失 → 先装 Evergreen Runtime |
| 0.4 | 确认能起一次构建 | `cargo --version` 之外，跑 `cargo new tmp-probe` 再删掉，确认编译链可用 |

**不通过就不进入阶段 1。**

## 2. 阶段 1 — 取证（半天）

**产物**：`design\tokens.lock.json`、`design\controls.md`、`design\parts\*`

| 步骤 | 动作 | 细节 |
|---|---|---|
| 1.1 | 写 `tools\extract-tokens.mjs` | 读 `resources\app.asar`（格式：8 字节头 + JSON 索引 + 数据区），按索引取出客户端包里的 theme/primitives 代码，正则抽 `--ds…` / `--json…` 定义点 |
| 1.2 | 抽取控件规格 | 从设置页相关 CSS 抽：卡片圆角、行圆角、按钮高、输入框高、chevron 尺寸与 stroke |
| 1.3 | 复制 parts | 需要复用的表面/菜单/滚动条 CSS 原样复制到 `design\parts\`，逐份算 sha256 |
| 1.4 | 合成基线 | `tokens.lock.json`：`{ generatedAt, sourceAsar:{path,sha256}, tokens:[{name,valueType,pkg,file,symbol}], parts:[{name,sha256}] }` |

**验收**：

```powershell
node tools\extract-tokens.mjs --out design\tokens.lock.json
node tools\extract-tokens.mjs --out design\tokens.lock.json.b
# 两次输出逐字节相同
(Get-FileHash design\tokens.lock.json).Hash -eq (Get-FileHash design\tokens.lock.json.b).Hash
```

- 名册里每个 token 都有 `pkg/file/symbol`；
- 抽不到的项显式进 `skipped: []`，不静默丢弃；
- `controls.md` 每条规格标注来源 `包/lib/文件.js:符号`。

## 3. 阶段 2 — 骨架（1 天，只读不启动）

**产物**：可运行的 Tauri 应用，能读配置、列实例、扫状态

| 步骤 | 文件 | 内容 |
|---|---|---|
| 2.1 | `package.json`、`src-tauri\Cargo.toml`、`tauri.conf.json` | Tauri 2 + Svelte + TS；窗口 1120×760，最小 900×600 |
| 2.2 | `src-tauri\src\store.rs` | `load_config/save_config/read_instance/write_instance/list_instances/validate_instance`；所有写走 `atomic_write`（tmp + rename） |
| 2.3 | `src-tauri\src\pointer.rs` | `read/write/restore/restore_default`；写前备份到 `desktop-next-location.json.launcher-bak` |
| 2.4 | `src-tauri\src\scan.rs` | 枚举进程（`sysinfo` crate 或 Win32 `CreateToolhelp32Snapshot` + `QueryFullProcessImageName` + PEB 取命令行），按规则匹配 home |
| 2.5 | `src-tauri\src\main.rs` | 注册 IPC：`config_get`、`config_set`、`instances_list`、`instance_save`、`instance_delete`、`pointer_read`、`pointer_restore_default`、`scan_status`、`version_scan` |
| 2.6 | `src\App.svelte` + `InstanceRow.svelte` + `PointerBar.svelte` | 按设计稿 6.1/6.2 渲染；样式只用 `tokens.lock.json` 里的变量 |
| 2.7 | `src\lib\api.ts` | 包装 `invoke`，统一错误码 → 中文文案映射 |

**验收（逐条可执行）**：

1. 手工把指针改成 `{"home":"C:\\Users\\<用户名>\\.dsh-b"}` → 启动启动器，顶栏显示 `.dsh-b`；
2. 开一个 DSH-NEXT（`.dsh`）→ 列表里对应实例显示「● 运行中」并给出 pid；
3. 改 `instances\*.json` 的 name 后重启启动器 → 列表反映新名字；
4. 把 `app.json` 删掉 → 启动器重建默认配置且不崩。

## 4. 阶段 3 — 启动管道（1 天，核心）

**产物**：串行启动队列 + 成功判定 + 失败回滚

| 步骤 | 文件 | 内容 |
|---|---|---|
| 3.1 | `src-tauri\src\launcher.rs` | `queue: Mutex<VecDeque<Task>>`；单 worker；每步向 UI 推 `launch:progress` 事件 |
| 3.2 | 启动流程 | 见设计 §5.4 伪代码；`pollIntervalMs=500`、`timeoutSec=90` |
| 3.3 | 失败分类 | E1003 占用 / E1004 版本无效 / E1005 超时 / E1006 启动即退出（带退出码）；失败一律回滚指针 |
| 3.4 | 恢复默认 | 成功后按 `restorePointerAfterLaunch` 把指针还原 `defaultHome` |
| 3.5 | UI 状态机 | Queued/Preparing/Spawning/Waiting/Running/Failed 六态；取消只停轮询，不杀已起进程 |

**验收（逐条可执行）**：

| # | 场景 | 期望 |
|---|---|---|
| A1 | 两个实例不同 home，连续启动 | 两个窗口、两条 host、各自 home 正确；排队提示出现又消失 |
| A2 | 两个实例配同一 home | 第二个被拒，E1003，指针不变 |
| A3 | 把版本目录的 exe 改名 | E1004，指针回滚为启动前值 |
| A4 | 启动后 90s 内杀不掉（人为阻塞） | E1005 + 指针回滚 |
| A5 | 实例运行中改指针 | **原实例不搬家**（Q1 观察项，记录结论） |
| A6 | 连续快速点两次启动 | 第二个进队列，不并发写指针 |

## 5. 阶段 4 — 停止 / 归档 / 删除（半天）

| 步骤 | 内容 |
|---|---|
| 4.1 | 停止：按 home 找到主窗口进程 → `CloseMainWindow`；15s 未退 → 弹确认 → `TerminateProcess` |
| 4.2 | 归档：`archived=true` → 移入「已归档 (N)」；恢复按钮置回 false |
| 4.3 | 删除：输入 ID 确认；默认勾选删数据；`defaultHome` 锁定不可删；`guard::assert_safe_delete_target` 兜底 |
| 4.4 | 删除后清理：实例文件、`app.json.lastPointer` 若指向它则置空、扫描缓存失效 |

**验收**：

1. 运行中三个按钮（归档/删除/编辑）全部禁用；
2. 归档后目录仍在，恢复后状态正确；
3. 对默认 home 实例点删除 → "删除数据"复选框灰掉，只能删记录；
4. 手工把 home 改成 `C:\` → 删除被 guard 拒绝。

## 6. 阶段 5 — 版本管理（半天）

| 步骤 | 内容 |
|---|---|
| 5.1 | `versions.rs`：`scan_versions()` 遍历 `versions\*`，校验 exe + asar |
| 5.2 | 读版本号：解析 asar 头（8 字节 + JSON 索引），取 `package.json` 的 `version` 与 `dependencies["@deepseek-ai/dsh"]` |
| 5.3 | 导入：选择已解包的目录，校验后写进 `versions\` 或只登记路径 |
| 5.4 | 改版本：只改实例配置，提示"数据在 home 里，不受版本影响" |
| 5.5 | 删版本：有实例引用则拒绝并列出引用者 |

**验收**：

1. 同时放 `2.0.21-next` 与 `2.0.20-next` 两个目录 → 列表里两个实例的第二行显示不同的壳/内核版本；
2. 把一个版本目录的 `app.asar` 删掉 → 标 invalid，选用时 E1004；
3. 实例引用某版本时删该版本 → 被拒。

## 7. 阶段 6 — 原生对齐门 + 打磨（半天）

| 步骤 | 内容 |
|---|---|
| 6.1 | `tools\verify-tokens.mjs`：扫 `src\**\*.{css,svelte}` 里每个 `var(--…)`，缺席即退出码 1；校验 `design\parts\*` sha256 |
| 6.2 | 文案：全部走 `zh/en` 字典；错误截断 45 字符 + `title` 全文 |
| 6.3 | 防呆：默认 home 无实例黄条；指针指向未知目录黄条；两者都可一键修复 |
| 6.4 | README：能力边界（AA 账号不隔离）、升级对账流程、故障排查 |

**验收**：

1. 在样式里写一个不存在的 `--dsw-xxx` → `verify-tokens` 退出码 1；删掉 → 0；
2. 改一份 `design\parts\*.css` 一个字节 → sha256 校验红；
3. 制造"默认 home 无实例" → 顶栏黄条出现且按钮可用。

## 9. 风险

| # | 风险 | 概率 | 影响 | 处理 |
|---|---|---|---|---|
| R1 | 当前工作区属主问题导致构建失败 | 中 | 无法开工 | 已改到应用根目录下工作（`danger-full-access` 可用） |
| R2 | Rust 工具链缺失 | 中 | 无法用 Tauri | 阶段 0 判定；缺则退 WPF（同一套模块划分） |
| R3 | NSIS 解包不可行 | 中 | 多版本功能受阻 | 阶段 5 先用 7-Zip 手工解一次验证 |
| R4 | 实例运行时改指针被重读 | 低 | 会打破隔离 | 阶段 3 A5 观察 |
| R5 | 解包版本树被自更新改写 | 中 | 共享版本被污染 | 记录现象；必要时实验禁更 |
| R6 | AA 账号跨实例共享 | 确定 | 无法隔离账号 | 写进 README 能力边界，不做承诺 |
| R7 | 路径含空格引发构建问题 | 中 | 构建脚本报错 | 全程加引号；必要时改名为连字符版本 |
