# 初始化向导（Onboarding）设计

> 状态：**已实现（1.0.3）**。实际流程与本文原规格有出入，差异见 §9。
> 本文既是最初规格，也是当前实现的说明；以 §9 为准。

## 1. 目标与非目标

**目标**：把"读文档才能用起来"降为"点下一步"。首次启动时在一个页面内完成：
语言 → 环境体检 → 默认数据目录树根 → 选 DSH-NEXT 版本 → 实例（可选试启动）。

**非目标**：

- 不做多步向导（分页/进度条），单页面板即可；
- 不做账号/云同步（本工具不需要网络）；
- 不替用户决定数据目录——只给默认值并允许改。

## 2. 触发条件

满足**任一**条件时，首次打开主界面后自动展开向导：

| 条件 | 判据 |
|---|---|
| 从未完成过向导 | `config.onboarding.completedAt` 为空 |
| 没有任何实例 | `instances/*.json` 数量为 0 |
| 没有任何可用版本 | `versions.csv` 扫描结果全部 invalid |

三条都满足时优先级最高（全新环境）。用户点「跳过」后写入
`config.onboarding.skippedAt`，此后不再自动展开，但设置页保留「重新运行向导」。

## 3. 单页面板结构（当前实现）

五块，自上而下，面板整体滚动，底部按钮 sticky 固定：

```
┌──────────────────────────────────────────────┐
│ ① 语言      [中文] [English]   默认跟随系统    │
├──────────────────────────────────────────────┤
│ ② 环境体检   ✓ 数据目录  ⚠ 指针不可写  ✓ WebView2 │
├──────────────────────────────────────────────┤
│ ③ 默认数据目录树根                            │
│   ✓ C:\Users\<用户名>   当前跟随系统默认        │
│   [选择目录]  [恢复默认]                    │
│   新建实例默认放在 …\.dsh-<ID>                 │
│   推荐改到非系统盘（树根在系统盘时才显示）        │
├──────────────────────────────────────────────┤
│ ④ 选择 DSH-NEXT                              │
│   [2.0.21-next · 内核 0.2.1-rc.4 ▾]          │
│   [导入安装目录…] / [去版本页导入]（无版本时）   │
├──────────────────────────────────────────────┤
│ ⑤ 实例                                        │
│   已有实例：✓ 默认 · default · C:\Users\…\.dsh │
│            [新建实例]                          │
│   无实例时：名称 / ID / 数据目录 表单           │
│   [启动看看]（可选）                            │
├──────────────────────────────────────────────┤
│              [跳过]        [完成并进入]        │
└──────────────────────────────────────────────┘
```

关键行为：

- **① 语言**：首次启动读 `navigator.language`（`zh*` → 中文，否则英文），
  选择后写 `localStorage['dshla.lang']`，设置页可随时改；
- **② 体检**复用 `permission_report`，只展示结果，不阻塞；指针不可写时给「以管理员身份重启」；
- **③ 树根**只做文件夹选择（系统选择器），选完立即生效；「恢复默认」清空为 `%USERPROFILE%`；
  与默认值相同时不显示「恢复默认」；树根与用户目录同盘时显示「推荐改到非系统盘」；
- **④ 选版本**：有可用版本时给下拉（带内核版本），始终提供「导入安装目录…」；
  没有任何可用版本时给出说明 + 两个入口（就地导入 / 去版本页）；
- **⑤ 实例**：**已存在实例时不再让用户重复填表**——列出已有实例，
  并给「新建实例」按钮：离开向导、写 `skippedAt`、直接打开主界面的新建对话框；
  没有实例时才显示名称/ID/home 表单（ID 用哈希规则，名称变化时跟随）；试启动并入本块；
- 「完成并进入」写 `onboarding.completedAt` 并关闭面板。

## 4. 数据结构

`app.json` 增加一个可选字段（旧配置读不到即视为未完成）：

```json
{
  "onboarding": {
    "completedAt": "2026-11-03T01:30:00+08:00",
    "skippedAt": null,
    "lastStep": 5
  }
}
```

| 字段 | 用途 |
|---|---|
| `completedAt` | 完成后不再自动展开 |
| `skippedAt` | 跳过时间；两者都为空时下次仍会展开 |
| `lastStep` | 中断后回到哪一步（0–5，0 = 未开始；越界值在 `sanitized()` 里夹取） |

## 5. IPC 契约

| 命令 | 入参 | 返回 | 说明 |
|---|---|---|---|
| `onboarding_state` | — | `OnboardingView` | 前端据此决定是否自动展开 |
| `onboarding_complete` | `{ lastStep? }` | `OnboardingView` | 写 `completedAt`（默认 `lastStep=4`） |
| `onboarding_skip` | — | `OnboardingView` | 写 `skippedAt` |
| `onboarding_reset` | — | `OnboardingView` | 清 `skippedAt` 与 `lastStep`，保留 `completedAt`；设置页「重新运行初始化向导」用 |

`OnboardingView` 字段：

```ts
type OnboardingView = {
  autoOpen: boolean;          // = completedAt 与 skippedAt 都为空
  completedAt?: string;
  skippedAt?: string;
  lastStep: number;
  environment: PermissionReport;   // 复用 permission_report，不新增探测
  webviewAvailable: true;          // 能看到面板就说明 WebView2 已工作
  hasInstance: boolean;
  instances: Instance[];           // 未归档实例：⑤ 据此显示「已有/新建」
  versions: VersionInfo[];
  userProfile: string;
  homeRoot: string;
  defaultHome: string;
};
```

## 6. 跳过与兜底

- **跳过**：写 `skippedAt`，主界面按现有默认值工作，不预建实例；
- **新建实例**：与「跳过」同样写 `skippedAt`（避免下次又弹），然后打开主界面新建对话框；
- **自动兜底**（任何一步失败都不阻塞）：
  - 体检失败 → 显示原因 + 「以管理员身份重启」，仍可继续；
  - 导入版本失败 → 保留已填内容，允许换目录重试；
  - 建实例失败 → 显示错误码与建议，允许改 ID/home 重试；
  - 无可用版本 → 明确说明 + 两个导入入口，「完成并进入」置灰并在底部写明原因；
- **重复进入**：设置页「重新运行初始化向导」清空 `skippedAt` 与 `lastStep`，保留 `completedAt`。

## 7. 验收标准

| 编号 | 场景 | 期望 | 状态 |
|---|---|---|---|
| O1 | 全新环境首次启动 | 自动展开；五块齐全；完成或跳过后主界面可用 | ✅ 已实测 |
| O2 | 点「跳过」 | 面板关闭；重启不再自动展开；设置页可重开 | ✅ 已实测 |
| O3 | 指针不可写 | 显示 ⚠ + 「以管理员身份重启」，仍允许继续 | ✅ 界面已验证（提权需人工点 UAC） |
| O4 | 导入无效版本目录 | 就地提示 `E1004`，不写入版本表 | 机制复用版本页，手工验收 |
| O5 | 中断后重开 | `lastStep` 持久化；单页面板重开即整页显示 | ⚠ 只做到持久化（见 §9） |
| O6 | 完成后新增实例 | 走普通新建流程，不再触发向导 | ✅ |
| O7 | 无可用版本 | ④ 说明 + 两个入口；「完成并进入」置灰并写明原因 | ✅ 已实测 |
| O8 | 已有「默认」实例 | ⑤ 列出实例并给「新建实例」；点击后关向导 + 打开新建对话框 + 写 `skippedAt` | ✅ 已实测 |
| O9 | 树根留空 | 视为跟随 `%USERPROFILE%`，不报错 | ✅ 已实测（含单测） |

## 8. 实现状态

按原计划的 1–5 步全部落地：`model.rs` 的 `OnboardingState`（serde 默认值保证旧配置兼容）、
`commands.rs` 的四个 IPC、`OnboardingPanel.svelte` + `App.svelte` 的展开判断；
单测覆盖「全新配置自动展开 / 跳过与完成后不再展开 / lastStep 夹取 / 老配置无 onboarding 字段仍可读」。

## 9. 与原规格的差异（1.0.3 实际实现）

| 原规格 | 实际 |
|---|---|
| 四块：体检 / 版本 / 实例 / 试启动 | **五块**：语言 / 体检 / 默认数据目录树根 / 版本 / 实例（试启动并入实例） |
| 未提语言 | ① 语言默认跟随系统 |
| 未提数据目录树根 | ③ 独立一块，只做文件夹选择，留空=跟随默认 |
| 实例总是新建 | ⑤ 已有实例时改为「用它 / 去新建」，不再重复建一条 |
| IPC 三个 | 四个（多 `onboarding_reset`） |
| `lastStep` 1–4 | 0–5，`sanitized()` 夹取 |
| O5「回到 lastStep」 | 单页面板无“跳步”概念，只持久化该字段 |
