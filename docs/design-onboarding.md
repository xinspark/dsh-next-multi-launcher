# 初始化向导（Onboarding）设计

> 状态：已设计，未实现。目标版本 1.1。
> 本文是给实现者的规格，不涉及具体视觉稿。

## 1. 目标与非目标

**目标**：把"读文档才能用起来"降为"点下一步"。首次启动时在一个页面内完成：
环境体检 → 选 DSH-NEXT 版本 → 建第一个实例 → 试启动。

**非目标**：

- 不做多步向导（分页/进度条），单页面板即可；
- 不做账号/云同步（本工具不需要网络）；
- 不替用户决定数据目录——只给默认值并允许改。

## 2. 触发条件

满足**任一**条件时，首次打开主界面后自动展开向导：

| 条件 | 判据 |
|---|---|
| 从未完成过向导 | `config.onboarding.completedAt` 为空 |
| 没有任何实例 | `instances/*.json` 数量为 0 |
| 没有任何可用版本 | `versions.csv` 扫描结果全部 invalid |

三条都满足时优先级最高（全新环境）。用户点「跳过」后写入
`config.onboarding.skippedAt`，此后不再自动展开，但设置页保留「重新运行向导」。

## 3. 单页面板结构

四块，自上而下，可滚动，底部固定一个主按钮：

```
┌─────────────────────────────────────────────┐
│ ① 环境体检                                  │
│   ✓ 数据目录可写   ✓ WebView2   ⚠ 指针不可写  │
├─────────────────────────────────────────────┤
│ ② 选择 DSH-NEXT                             │
│   [导入安装目录…]  或从已登记版本下拉选择     │
│   版本 2.0.21-next · 内核 0.2.1-rc.4         │
├─────────────────────────────────────────────┤
│ ③ 第一个实例                                │
│   名称 [日常]   ID [inst-3f2a91c8]           │
│   数据目录 [%USERPROFILE%\.dsh-<id>] [改]    │
├─────────────────────────────────────────────┤
│ ④ 试启动（可选）                            │
│   [启动看看]  → 状态：启动中… / 成功 / 失败   │
├─────────────────────────────────────────────┤
│              [跳过]        [完成并进入]      │
└─────────────────────────────────────────────┘
```

关键行为：

- **① 体检**复用现有 `permission_report` 与数据目录探测，只展示结果，不阻塞；
- **② 选版本**支持"导入目录"（等于现有的登记版本流程），导入后立即校验 `DSH NEXT.exe` 与 `app.asar`；
- **③ 实例**的 ID 用现有哈希规则，名称变化时若用户未手改 ID 则跟随（与新建对话框一致）；
- **④ 试启动**是可选按钮，走现有 `instance_launch`，失败时把 `E1001/E1004/E1005` 的解释就地展示；
- 「完成并进入」写 `onboarding.completedAt` 并关闭面板。

## 4. 数据结构

`app.json` 增加一个可选字段（旧配置读不到即视为未完成）：

```json
{
  "onboarding": {
    "completedAt": "2026-11-02T16:30:00+08:00",
    "skippedAt": null,
    "lastStep": 3
  }
}
```

| 字段 | 用途 |
|---|---|
| `completedAt` | 完成后不再自动展开 |
| `skippedAt` | 跳过时间；两者都为空时下次仍会展开 |
| `lastStep` | 中断后回到哪一步（1–4） |

## 5. IPC 契约

| 命令 | 入参 | 返回 | 说明 |
|---|---|---|---|
| `onboarding_state` | — | `{ completedAt, skippedAt, lastStep, environment, versions, hasInstance }` | 前端据此决定是否自动展开 |
| `onboarding_complete` | `{ lastStep }` | `null` | 写 `completedAt` |
| `onboarding_skip` | — | `null` | 写 `skippedAt` |

环境对象复用现有结构，不新增探测逻辑：

```ts
type OnboardingEnvironment = {
  dataDir: { path: string; writable: boolean };
  webview: { available: boolean; version?: string };
  pointer: { path: string; writable: boolean };
  isAdmin: boolean;
  needsElevation: boolean;
};
```

## 6. 跳过与兜底

- **跳过**：写 `skippedAt`，主界面按现有默认值工作（`defaultHome`、空版本列表），
  不预建实例——用户可以从「新建实例」开始；
- **自动兜底**（向导期间任何一步失败都不阻塞）：
  - 体检失败 → 显示原因 + 「仍然继续」；
  - 导入版本失败 → 保留已填内容，允许换目录重试；
  - 建实例失败 → 显示错误码与建议，允许改 ID/home 重试；
- **重复进入**：设置页「重新运行初始化向导」清空 `skippedAt` 与 `lastStep`，保留 `completedAt`（不强制）。

## 7. 验收标准

| 编号 | 场景 | 期望 |
|---|---|---|
| O1 | 全新环境（无配置、无实例、无版本）首次启动 | 自动展开向导；完成三步后主界面可用 |
| O2 | 点「跳过」 | 向导关闭；重启应用不再自动展开；设置页可重新打开 |
| O3 | 体检发现指针不可写 | 显示 ⚠ 与「以管理员重新启动」，但仍允许继续 |
| O4 | 导入无效版本目录 | 就地提示 `E1004`，不写入版本表 |
| O5 | 向导中断（关窗口）后重开 | 回到 `lastStep` |
| O6 | 完成后新增实例 | 走普通新建流程，不再触发向导 |

## 8. 实现顺序建议

1. `model.rs` 加 `OnboardingState`（含 serde 默认值，保证旧配置兼容）；
2. `store.rs` 加读写与 `sanitized`；
3. `commands.rs` 三个 IPC（薄封装，复用现有逻辑）；
4. 前端 `OnboardingPanel.svelte` + `App.svelte` 的展开判断；
5. 单测覆盖 O1/O2/O5/O6（状态机），O3/O4 走手工。

> 不在 1.0.0 的范围内：1.0.0 以「文档 + 提示条」承担首次使用引导。
